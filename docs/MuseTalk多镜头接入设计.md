# MuseTalk 多镜头接入设计

2026-11-15。原版镜头编辑器的形象、时长、排序、均分音频、取消回滚已实现；当前 MuseTalk 在界面、请求快照和自动流程均明确拒绝多镜头。本轮补实际生成，不改已有镜头编辑交互，不冒称采用原厂内部算法。

采用串行逐镜头真实推理，复用已经验证的 v2 单镜头工作器与回执；各镜头完成后裁取计划帧数，拼接画面，并一次封装完整原音轨。模型会逐镜头重新加载，增加启动开销；不引入未经验证的新工作器协议。某镜头失败或取消则整条任务不登记视频，保留各段证据，不自动重交。

时间轴以16k规范化音频实际采样数为准，总帧数向上取整。镜头总配置时长允许0.051秒的十分之一秒舍入误差；内部切点按累计时长四舍五入到帧，末镜头覆盖全部剩余帧。输出采用第一镜头画幅和整数帧率；低于10fps的源统一提升到10fps，使编辑器0.1秒镜头有可显示帧。不同画幅等比例缩放、黑边补齐，不拉伸或裁人物，记录转换策略。

每镜头的原音频切片按累计帧边界映射到采样，记录起止及至多一个采样的整帧修正。短于1秒的镜头仅为模型推理补静音到1秒，再严格裁回请求帧数；补入的静音及额外画面不进入最终成片。最终音轨使用完整原文件，不变速、不按镜头切拼，因此不累积音频漂移。该策略能接通短镜头，不代表已经证明其口型质量。

复用来源按实际镜头选定，不依赖单形象遗留字段。所有源文件属性和SHA进入输入证据，开始前及最终登记前核对。归一化素材最多处理该来源最长镜头所需动作片段，工作器仍只提取一个源动作周期，避免600秒全量PNG缓存。
