# 发行版代付与额度设计（P1，未实施）

记录日期：2026-11-25。本文件是接口与责任边界设计，不代表已有中转服务、账户余额、支付渠道、供应商报价或代付能力。P0离线软件授权与在线代付分别管理：永久授权的 expiresAt=null，不依赖联网心跳；仅使用代付云端能力时才需要中转网络。买家仍需自备 Python、模型权重与可用本地推理环境。

## 能力边界

P1拟仅支持文本与视觉理解的代付。图像生成与视频生成不支持代付，必须使用买家本机 ComfyUI；服务端拒绝 image/video 计费请求，客户端选择限制不能替代服务端检查。视觉理解指对输入图片作描述/识别，与生成图片不同。

P0现有文本/视觉供应商接口继续复用：云端记录请求次数与usage，真实本地推理不占云端额度。客户端 usage.json 是本机防误用与成本提示机制，不是防篡改账本；P1余额及扣费以中转服务的账本为准。P0不应向买家宣传已包含代付余额。

## 中转接口（拟定，未部署）

| 接口 | 请求要点 | 返回与约束 |
| --- | --- | --- |
| POST /v1/sessions/exchange | 软件授权证明、账户验证材料、设备摘要、客户端版本、一次性挑战 | 短期访问令牌与续期材料；验证激活码签名不能代替账户鉴权，客户端不持有软件发行私钥 |
| POST /v1/text/generations | 模型白名单标识、messages、max_output_tokens、idempotency_key | request_id、文本、实际usage、费用口径版本、余额；不允许任意供应商baseUrl或任意模型 |
| POST /v1/vision/analyses | 模型白名单标识、文本、受限图片、max_output_tokens、idempotency_key | 与文本统一账本；限制图片数量/像素/请求大小，不接受任意内网URL抓取 |
| GET /v1/requests/{request_id} | 当前账户访问令牌 | pending/succeeded/failed/unknown、已知usage与费用；结果不明时查询原任务，避免重交造成重复计费 |
| GET /v1/usage | 日期区间、分页 | 已结算、预留、估算、退款及余额；不回传上游密钥 |
| POST /v1/sessions/revoke | 当前会话或设备标识、账户验证 | 吊销在线会话，不影响已售出的离线永久软件授权 |

以上路径是设计建议，不可在P0界面显示为已可调用。发布实现前需冻结版本化schema与错误码，并增加真实中转验收。激活码不是可公开传播的登录凭据，也不能直接换取无限代付权限。

## 令牌与密钥生命周期

上游供应商密钥只保留在中转服务器的密钥管理系统，不进入客户端、安装包、仓库、日志或错误提示。客户端拿到的是用途、账户、设备与能力受限的令牌，凭据落盘使用系统加密存储。

建议访问令牌短时有效、续期令牌轮换且可撤销；具体有效时长、绑定设备数量和身份核验方式须在上线前由发行方确定，本文件不虚构既有规则。服务端校验audience、用途、有效期与撤销状态；每次续期替换旧凭据，检测到重放或异常消费可冻结在线代付。离线永久使用本地能力不读取在线会话状态。

软件签名私钥与代付服务凭据分开保管。离线授权发行私钥泄露涉及伪造软件授权，不能通过静默联网吊销损害永久授权承诺；应制定公开换钥和合法用户换码方案。中转凭据泄露则由服务端撤销、轮换与审计处理，不需要把新上游密钥下发给客户端。

## 计费口径、并发与熔断

每个请求先按账户、设备、能力、模型和最大输出预留预算，再提交上游；服务端原子维护预留与结算，idempotency_key在同账户下唯一。重复提交同一业务键返回原任务，不能再次扣费。usage记录供应商请求ID、输入/输出token、缓存口径、模型/价格版本与币种；不记录买家正文或图片，除非取得单独同意并约定保留期限。

收到可信usage后按真实口径结算并释放多余预留。无usage、截断、超时、断线和取消并不自动等于零费用；任务保持待核对或按显式估算显示，不凭空编造实际token。退款/补记使用独立账目，不覆盖旧交易。若供应商只能查询异步任务，先查原请求再决定重试。

默认P0限制是每日云端请求10次、token 200000，可配置，文本与视觉共用池；连续3次上游失败按能力当日熔断，次日恢复。P1应另设服务端账户/设备/并发/单条预算上限，不能信任客户端上报余额。自然日使用明确时区（本轮模块默认Asia/Shanghai），跨日与时钟回拨必须有一致规则。额度耗尽只返回中文可执行提示，不自动改为收费更高模型、赊账或继续代付。

## 单条成本测算

当前没有经确认的供应商、币种、计价版本或实际usage，因此暂无可靠信息，无法给出真实单条金额，也不填造假的价格示例。上线前应使用供应商正式报价与同类型真实请求记录填写以下公式：

`单条上游成本 = 未缓存输入token × 输入单价 / 计价基数 + 缓存输入token × 缓存单价 / 计价基数 + 输出token × 输出单价 / 计价基数 + 已确认的图片或其他计费单位费用`

`单条完全成本 = 单条上游成本 + 可归因的中转网络/存储费用 + 支付手续费 + 实际税费与币种兑换费用`

若供应商输入token已经包含缓存token，必须先按其正式口径拆分，禁止重复计算；视觉服务若按图片/像素/其他单位计价，应使用对应正式口径，不能硬套纯token公式。没有缓存价格则不能假设享受折扣。报价日期、币种和计价基数随模型/价格版本留存；估算与实收在界面分开显示。有限次重试、截断输出与思考token若被计费，也须按供应商实际记录计入，不能只统计用户看见的字数。

## 超额策略与责任边界

买家可选择停止请求、等待次日额度恢复、购买经明确报价的在线额度，或在原工作台手动切换已配置本地模型；不得无提示自动转付费能力。预算不足时在上游提交前拒绝，并释放本次未提交预留。服务端故障不能损坏本地草稿或阻止已授权本地能力启动。

发行方负责中转服务器、上游密钥、服务端预算控制和账本审计；买家负责自身账户凭据与设备使用。泄露造成的费用归属需依账户合同、供应商记录和实际泄露原因核定，不能在没有事实或约定时一概归责买家。疑似泄露时先冻结相关在线令牌、保留最小审计证据并通知责任人，不泄露密钥内容。

## P1上线前门禁

真实中转需另行验收账户鉴权、短期令牌轮换与重放、并发预留、幂等扣费、跨日熔断、usage缺失与补记、异常退款、服务器密钥扫描，以及图/视频请求服务端拒绝。必须取得实际供应商价格和真实单条请求账单，才可对外公布代付价格或包含额度。本P0没有实施上述在线功能。
