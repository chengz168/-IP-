# 桌面声音拖拽修复验收

验收日期：2026-11-16。范围仅为声音上传拖拽、原生文件导入及本地入口权限；本批没有执行模型下载、付费调用或新声音生成。

## 原因与修改

实际查询 Win32 `OpenProcessToken` 和 `GetTokenInformation(TokenElevation=20)`：旧工作台主进程 PID 16628 为管理员权限，Explorer PID 1496 为普通权限。Windows 会限制普通 Explorer 向管理员窗口拖放。这是已核实的环境问题，不能只改页面事件后就宣称桌面拖拽已恢复。

`scripts/launch-local-workspace.cjs` 新增调用 `scripts/windows-normal-launch.ps1`：管理员父进程通过已有 Explorer 桌面的 `ShellExecute` 启动工作台；普通父进程保留原启动方式。未改变 UAC 或系统安全策略。已有会话仍沿用单实例唤起逻辑，避免擅自关闭用户任务；已有管理员实例需要关闭后重新启动。

声音上传新增 Electron `webUtils.getPathForFile(File)` → `studio:dropVoice` → 主进程 `service.importPath` 的本机文件链路。主进程再次检查主窗口主 frame 来源、绝对路径、允许扩展名、单个文件与 50MB 大小限制；返回素材信息时不暴露本机路径。浏览器和内存 File 保留原字节导入兼容。拖放区域增加进入、离开、复制光标及事件阻止行为。

## 验收步骤与结果

- `node --test tests/voice-drop.test.cjs tests/electron-instance-lock.test.cjs`：4 项通过、0 失败、退出码 0。覆盖原生桥接、主进程来源和文件校验、路径信息隐藏、浏览器兼容及单实例入口。
- `npm run build`：4247 个模块，10.55 秒，退出码 0；构建仍提示现有 JS 分块体积较大。
- 在独立工作区 `evidence/validation/voice-drop-20261116/workspace`、端口 9382，通过修改后的日常启动器启动 PID 30092。
- 通过 CDP `Input.dispatchDragEvent` 的 `dragEnter`、`dragOver`、`drop`，注入实际磁盘 WAV 文件路径；没有用 `new File` 或 file input 替代该拖放测试。导入文件 SHA256 与磁盘原文件一致，音轨波形读取成功，填写名称后保存按钮可用。
- 错误格式、多文件、超过 50MB 均拒绝，素材库无部分导入。
- 点击上传区域打开 Windows 原生文件选择框，经真实原生窗口选取同一个 WAV 后，文件名、波形及样本编辑器正常。
- 隔离窗口 PID 30092、用户重启窗口 PID 33868、Explorer PID 1496 实测 `TokenElevation=false`。本子任务仅连接 CDP 9382，未连接 9345 或 9381；但下述 Win32 鼠标尝试存在误落日常工作台的情况。
- 测试后已关闭自建 9382 窗口及自建资源管理器测试窗口。

## 验收边界

CDP 真实磁盘文件拖放链路已通过。另尝试从隔离资源管理器窗口使用 Win32 鼠标拖放，9382 未观察到拖放事件；随后主代理只读查看日常 9345 窗口，发现上传声音弹窗已有“桌面拖拽验收.wav”。结合测试文件名与桌面前景窗口覆盖情况，该次鼠标尝试疑似误落日常窗口，造成日常素材导入，不能声称日常数据未变化。没有点“保存声音”，没有关闭日常弹窗，已停止所有桌面鼠标和键盘操作并保留现场。该次尝试不计为具有准确窗口跟踪的真实 Explorer 鼠标验收通过；普通权限修正及 CDP 通过不替代用户实际鼠标拖入确认。

本次测试使用 2 秒正弦波 WAV，只验证上传、字节一致及样本编辑就绪，不证明声音生成质量或克隆效果。
