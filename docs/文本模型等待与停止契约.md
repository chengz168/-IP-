# 文本模型等待与停止契约

## 问题与范围

当前文本、语音、视觉及服务桥共用180秒HTTP请求超时。本机27B文本模型仍在持续生成时会被这个固定等待期限截断；本次只将文本等待期限独立配置，不扩大其他能力的等待期限，也不自动重试模型请求。

## 配置与执行

- 新增可选`provider.textTimeoutSeconds`，允许空值或30至1800的整数秒。数值输入与数字字符串均接受，保存为字符串；非法值在改设置、写密钥或写盘前拒绝。
- 空值时，本机Ollama文本默认600秒；兼容云端文本默认180秒。设置页展示单位、范围及按来源采用的默认值。
- 文本有效超时写入`generationConfig`不可变请求快照，并写入实际请求证据`transportTimeoutMs`。设置改变后，既有请求按其开始时的值执行，迟到结果依据快照匹配规则处理。
- `Providers.request`新增可选第四参数`timeoutMs`，原调用仍默认180000毫秒；仅`Providers.text`主动传入文本有效超时。
- 用户停止信号始终与期限信号合并，任何自定义abort reason也必须识别为“请求已停止”，不误报网络连接失败。超时仍提示“模型服务请求超时”。不宣称本地HTTP断开等于远端引擎一定已停止计算。

## 验收与恢复

使用本地延迟HTTP夹具及request第四参数的毫秒级短期限验证真实超时、停止及自定义reason；文本用户配置仍维持30秒下限，不为测试放松校验。定向验证本机/云端默认、自定义值传递及证据、非法设置不写盘、请求快照变化、其他能力保持180秒。无真实模型调用，无自动重试或模型下载。

错误时原文、既有配置和密钥保持；用户可清空文本等待设置恢复对应来源默认值。完成定向测试后冻结文件，由主代理统一构建与全量检查。
