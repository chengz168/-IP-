# 商品脚本驱动的产品介绍视频

本批针对用户明确提出的“根据商品详情、商品图和图标素材写文案，再按文案生成产品介绍视频”，修正仅展示原图的范围偏差。

## 七步接续与验收

1. 第一步采集/上传商品资料与素材，标注商品图、详情图、图标用途；由模型生成开场需求、特点解释、细节说明、结尾引导的脚本，每镜包含卖点、依据、画面、动作、运镜及参考图。
2. 第二步核对事实并确认正文，第三步使用现有声音配置生成完整旁白；不重复配音。
3. 第四步使用确认稿及真实音轨时间轴准备产品介绍分镜，沿用现有图片、动态视频、候选确认、任务恢复与合成服务。用户可以重新生成或改动作，原图展示作为旧任务兼容模式。
4. 主体动态由已配置图生视频服务生成；图标、参数与文字不交给视频模型臆造。图标作为独立原素材绑定并在合成时精确叠加；没有图标则不虚构。
5. 旁白不裁词、不循环、不静帧补时；每镜与对应台词关联。识别段内部边界只能插值估计，必须明确时间依据。H3短镜头生成至少4秒，剪去真实多生成部分；超过15秒要求拆镜，不重复图像冒充生成。
6. 合成后交接现有第五、六、七步，保留当前确认稿和音频。不上传或公开发布。

## 模块与实现边界

- `product-studio`：脚本丰富、图像角色、准备产品介绍分镜。
- 新的产品介绍控制器与前端：调用已有 StoryStudio 动态生成和恢复，复用其任务模型，不另建GPU队列。
- `story-generator`：仅产品介绍合成分支使用独立旁白，避免混入模型生成对白；按计划裁真实视频并叠加原图标和准确卖点文字。
- 旧商品原图展示不作为产品介绍模式的静默回退。动画生成失败、缺权重、待确认任务均明确呈现。

## 实测要求与恢复

必须实际模型出图/出视频、完整成片播放及抽帧检查；区分媒体有效与商品外观、动作和内容质量接受。保留旧草稿、素材和密钥配置，每批构建后更新实际本地软件。待确认远端任务按原ID查询，不以重交代替恢复。授权仓库仅提交源码，不提交私有音色、商品素材、模型及本地证据。
