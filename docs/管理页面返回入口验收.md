# 管理页面返回入口验收

日期：2026-11-16。问题：形象管理页只有右上角菜单可以切回工作流，缺少直接可见的返回按钮。

## 本批交互

- 管理页、设置、任务中心和帮助页的固定标题栏显示“← 返回”，带明确的目标页面提示和可访问名称。
- 记录本次访问的页面顺序，返回上一页并保留工作流视图与当前任务步骤。重复点击当前菜单项不新增历史。
- 从菜单明确切回新/旧工作流、创建或选中任务时清空管理页返回历史。
- 返回前沿用现有草稿保存流程，保存失败留在原页并显示错误。本批不新增资源表单自动保存；资源仍需使用原有保存按钮。

## 验收清单

| 检查 | 预期 |
| --- | --- |
| 新工作流进入形象管理后返回 | 回到同一任务、原步骤和新工作流 |
| 旧工作流进入形象管理后返回 | 回到旧工作流 |
| 形象管理进入设置，连续返回 | 先回形象管理，再回原工作流 |
| 重复点击形象管理菜单 | 不形成返回自身的历史 |
| 键盘焦点与 Enter | 可聚焦并执行返回，焦点轮廓可见 |
| 页面向下滚动 | 顶部返回仍在视口内，无内容遮挡 |
| 1400×1000 与 1100×760 大字号 | 标题栏无横向越界，与品牌、菜单、窗口按钮保持间距 |
| 数据保护 | 返回不创建新任务、不修改最终稿和已有声音/形象 |

## 实际结果

- 独立 Electron 端口 9382（PID 32936）通过实际菜单和返回按钮验证：新工作流从第四步进入形象页，返回后仍是该任务第四步；旧工作流进入形象页后，用键盘 Enter 返回旧工作流。
- 形象管理 → 设置 → 返回形象管理 → 返回新工作流通过；重复点击当前形象管理菜单不产生多余返回层级。
- 声音、素材、任务、账号、设置、帮助页均实际进入并点击返回，回到新工作流。
- 1400×1000 原生窗口截图已查看；1100×760 视口大字号截图已查看。返回按钮最小高度 44px，无横向越界，品牌和右侧菜单间距保留；实际键盘 Shift+Tab 的焦点轮廓为 2px。
- 滚动形象管理内容后，返回按钮仍位于固定标题栏内。导航前后核对任务 ID、步骤、原文、最终稿、声音/视频引用和形象声音资源均一致。
- 第一次旧工作流检查误用了新工作流的步骤选择器，导致验证脚本超时；修正检查目标后通过，不将首次脚本检查记为通过。
- `node --test tests/copy-confirmation.test.cjs tests/typography.test.cjs tests/workflow-view.test.cjs`：24 项通过、0 失败、0 跳过，退出 0。`npm run build` 退出 0，保留现有大分块体积警告；`git diff --check` 通过。
- 日常 9345 页面在只读确认资源表单为空后刷新，并通过菜单恢复形象页。当前任务整份草稿、形象、声音及模型配置与刷新前一致，按钮可见。
- 自建 9382 验证窗口在验收后关闭；日常窗口保留在形象管理页。

证据目录：`evidence/validation/page-back-20261116/`，含两尺寸截图、`functional-report.json` 和 `daily-update-receipt.json`。本批不涉及声音或视频生成质量，也不承诺未点击保存的资源表单跨页自动恢复。
