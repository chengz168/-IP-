# 当前流程状态与历史执行分离

日期：2026-11-14。整体复刻目标保持active。本批修正真实巡检暴露的状态冲突，不修改原厂软件数据。

## 已确认问题

- task-state无条件将历史awaiting_publish映射为“成片就绪，待发布”；App和WorkflowStatus直接使用相同历史记录，未检查当前产物有效性。
- 草稿改速、改字幕或改封面后，Store已经解除相关结果引用，但页面仍显示待发布。
- 手选视频的自动流程明确跳过配音，七阶段摘要仍把配音当作第一个缺失步骤，待发布任务显示“当前步骤：声音生成”。

## 实施契约

1. 原始workflowJobs、阶段状态、快照和run历史保持不变。新增只读的当前状态投影；输入变化、当前文件丢失/类型不符、缺少标题描述标签或发布素材改选时不沿用历史待发布。
2. 当前制作输入与流程完成时expectedInput核对，排除步骤、页签、任务名称、字号、导出记录等界面或导出变化。声音/视频/剪辑/封面参数与结果是制作签名；新旧界面共用规则。
3. 主进程检查真实文件普通/非空/类型。页面编辑未保存前也能立即显示输入变化；保存后与任务中心一致。切页或导出本地发布包不使有效产物过期。
4. 只有有明确跳过配音记录、已复用的相同视频源、相同已确认文案的任务才把配音阶段显示“已跳过”。不伪造音频文件或把跳过写成成功生成。
5. 待发布的当前步骤应为视频发布，七阶段完成度仍不等于真实发布；未知远程结果优先于旧待发布，不能隐藏或自动重交。
6. 可重新处理时提供明确入口；流程运行/排队/停止/失败/未知的已有锁与取消语义保持。

## 影响、恢复与验收

- server/workflow-view.mjs用于前后端共用投影；task-state使用真实文件检查并给出当前阶段/跳过进度。
- App/WorkflowStatus使用投影，TaskCenter明确区分当前提示与历史执行；保留原布局，只增加必要状态反馈。
- 契约测试覆盖完成→切页/导出→改参数→丢文件/改类型→保留历史→新任务恢复；真实源码Electron使用既有媒体副本工作区操作，原用户工作区完整JSON前后相同。
- 只在独立目录进行修改/渲染/临时文件移动；不调用平台发布或下载模型。最终build、目录包与哈希，打包EXE历史启动拒绝继续保留。
- 如出现回归，回退新增投影及消费代码，不回写或重命名历史记录；既有真实素材文件保留。
