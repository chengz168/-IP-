# IP大脑分享链接识别修复

## 原因与变更

账号学习入口原先直接对输入调用 `new URL`，整段抖音账号分享文字会被误判为无效网址。本次把已有单视频分享解析抽为前后端可复用的纯函数，保持单视频接口兼容，账号入口识别唯一 HTTP/HTTPS 链接、保留草稿原文，并将规范URL传入已配置的采集桥。

明确的抖音作品地址会提示使用“提取文案”或“视频拆解”；多个链接、数字账号和带凭据的网址被拒绝。短链只完成语法识别，尚未解析其跳转目标，不代表已确认账号类型或获取作品。

页面提前显示账号主页采集未配置的原因、本地学习样本入口和设置入口。未配置时不可提交账号学习，输入无效也不会清空已有样本。后端保留同样的校验，不将保存链接、空样本或未知远程任务标记为学习成功。

## 复用检查

优先检查并复用 `server/local-link-extractor.cjs` 的已有解析函数。Google Chrome 专用调研会话查询 GitHub 的 linkifyjs；搜索导航超时，候选页导航曾连接重置，随后确认候选页完成渲染并读取 README。官方仓库 `nfrasser/linkifyjs` 声明 MIT、支持 Node 18+，页面可见 release v4.4.0。未检出固定提交或审阅源码，因此未引入第三方代码。该库负责文字中的链接识别，不提供抖音账号作品采集；本次无需新增依赖或模型。

## 验证

- 单次回归：`node --test tests/share-link.test.cjs tests/brain.test.cjs tests/brain-video.test.cjs tests/brain-review.test.cjs tests/local-link-extractor.test.cjs tests/batch-link-extraction.test.cjs`，退出码0；70项，67通过、0失败、3项因媒体环境条件跳过。
- 单次界面构建：`npm run build`，退出码0；仍有打包体积提醒。
- 真实 Electron：保留用户整段分享文字，确认识别出的URL、缺少采集服务提示、本地文案/视频样本弹窗、设置入口、账号采集设置为空、错误输入提示和底部按钮可滚动到达。
- 真实 IPC 提交当前账号学习，返回“已识别账号分享链接，但主页采集服务尚未配置”；未产生伪学习档案，草稿、素材、声音与模型配置保留。
- 本地入口完成备份、正常关闭和启动更新，验证在实际本地应用完成。

## 尚未完成的能力

当前本地配置没有可调用的账号主页采集服务，因此“粘贴账号主页 → 自动取得多条作品文案 → 学习账号”尚不能运行。现有单视频浏览器提取不提供账号作品列表采集。本次属于链接识别与状态提示修复，不是账号自动采集功能的交付。
