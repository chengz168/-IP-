# 模型来源选择与发现设计

日期：2026年11月16日。用户要求模型设置同时可选云端服务与本机已有模型。本批属于实施设计，未完成项不得当作已交付。

## 行为

文案、视觉、配音、语音识别及数字人口型按能力选择现有接入方式。已支持的本地引擎包括Ollama、IndexTTS、Windows系统音色、Whisper、MuseTalk和已有ComfyUI/H3路径；具体是否安装、服务启动或能力可用，以发现与检查结果为准。没有统一模型列表的服务继续允许手填自定义名称，并标注尚未验证。

选择来源、刷新模型和查看本地状态只作用于设置草稿，不保存配置、不触发生成或自动下载。列表只来自真实服务响应和配置环境检测，列表缺少当前模型时保留当前值。云端接口未声明能力时显示能力未知，不凭名称推测视觉、语音或嵌入支持。刷新失败显示所在能力的错误和重试入口，旧请求不能覆盖新来源的列表。

文案、配音与识别原先共用Base URL。新界面必须支持混用本地文案与云端配音/识别，后端使用每种能力自己的地址覆盖；空覆盖延续旧Base URL回退。保存的模型、发现请求和实际执行请求要使用相同路由。密钥延续系统加密存储，不写入列表、证据或业务素材；本机Ollama查询不携带云端密钥。

本地目录检查只能证明路径和必要文件存在，不能标成模型已加载或可生成。涉及Python依赖、CUDA或实际模型加载的额外检查须明确其检测范围，不借列表刷新偷偷启动大模型推理。

## 分工与边界

| 角色 | 工作 | 交付 |
| --- | --- | --- |
| 前端研发 | Settings表单、共享模型选择器、来源草稿、异步状态与布局 | 明确保存前后行为、真实界面截图、定向验证 |
| 后端研发 | 只读发现action、字段保存、各能力路由、超时和凭据处理 | 精确契约、真实本机发现、定向回归 |
| 产品测试 | 隔离UI、受控HTTP异常与真实本机列表复验 | 请求记录、保存前后对比、失败与阻塞保留 |
| 负责人 | 接口/文件边界、整合、日常入口加载与代码提交 | 阶段收据和未完成项 |

三个角色通过既有聊天直接对齐契约，负责人统一整合。测试不改产品源码；同一文件不得交给多个角色同时修改；主工作区不作为切换模型的试验场。

## 接受条件

1. 本机服务真实列出的模型可选；服务不可达和空列表有明确不同状态。
2. 云端兼容列表可读取，未列出模型仍可手填；不把受控接口夹具当真实云端证明。
3. 选择、保存、重进和重载结果一致；未保存切换不污染原配置。
4. 刷新不替换当前模型、不新增运行、不改变当前视频任务；加载、错误、重试可操作。
5. 本地与云端混用时端点和生成路由一致，不能把云端配音发给本地文本服务。
6. 真实能力、未知能力、仅已配置路径和未安装状态明确区分。
7. 两种窗口尺寸和四种字号下控件对齐、内容可达；不以几何检查代替原版全页面一致性验收。
