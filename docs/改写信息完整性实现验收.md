# 改写信息完整性实现验收

2026-11-14。上一轮为 progress，整体完整复刻目标 active。本批处理实际样本中的压缩、动作弱化及通知条件表达不清，不把扩大拦截等同于改善生成。

## 设计

- 原软件可见577字模板保持原文。仅对该模板的本地请求包装改进：固定开头后，将剩余原文分成有顺序的信息单元，每个单元都有原文依据。模型逐单元重组表达，必须覆盖完整对象、条件、数字和先后顺序；不靠新增效果或空话凑长度。
- 返回结构包含全部单元的正文。服务验证编号齐全且无额外单元、非空和显式数字/型号，按原文顺序组装，不要求模型JSON属性顺序一致。逐段及总长偏差提示复核，不作为事实错误直接拒绝。这是覆盖结构和有限字面验证，不能声称自动理解每项动作；实际样本仍需对照原文检查。
- 当结构或显式事实不满足时保留实际请求及原始回包，不偷偷补写、不改用户稿、不自动循环消耗模型。合理改写的否定同义表达仍提示复核，不为提高通过率降低明确反转校验。
- 为压缩问题提供明确长度区间和完整信息要求；输出过短/过长展示具体复核原因，不把所有长度差都当事实错误。一般模板维持已有执行，不擅自更换用户模型或全局模板。
- 记录本地包装版本、信息单元、原始响应和最终组装稿；原文、模板、模型或目标字数变化时，沿用当前快照/过期保护。

## 验收与恢复

1. 新增结构、截停边界、前导空白/引号、信息单元缺失、数字变化和失败留证的有意义测试，保持现有测试通过。
2. 使用上一轮虚构的操作、产品、活动输入，先在已有27B本机模型做真实同输入对照，不下载、不调用原厂服务；根据结果再决定是否需要针对其他已装模型验证，不盲目重试。
3. 逐项人工核对对象、动作、数字、否定与条件、自然度、长度和重组程度；如仍不足，明确记录问题，不能以结构合格证明内容可发布。
4. 实际源码桌面验证生成/保存刷新，以及运行中编辑、失败/原稿保护。必要的构建和目录包哈希完成后，恢复原工作区完整JSON含updatedAt与原模型。
5. 最终收据分类 progress；未验证声音/口型与全部原厂效果不冒称完成，不运行历史被自动审批拒绝的独立EXE。
