# 人物优化后端契约

独立入口 `avatarOptimize({id?,avatarId,look,background})` 中 look 为 natural/original，background 为 original/business-studio。两项均original表示没有变更，拒绝执行。配置 portraitPython 必须是已安装Python绝对路径；business-studio 另需已存在非空 portraitModel ONNX文件。执行不下载模型和依赖。

输入用现有prepareVideoSource建立临时正向CFR副本。原件及来源形象在处理前后核对哈希/数据快照，变更则拒绝登记。回执包含原件、规范副本、模型及输出SHA256和规范化参数。输出尺寸、帧率、帧数、时长对照规范副本，原音轨全部复制并核对数量、codec、时长，最后FFmpeg整片解码。

自然处理仅从原片亮部低饱和候选估计固定增益，全片沿用，在背景合成之前应用；无足够中性色候选则使用单位增益。参数限幅0.88～1.14，轻微平滑与锐化，不改变脸型、身份、服装或动作。不能据此宣称人脸修复、曝光恢复或画质达到参考软件。

背景使用RVM真实alpha及前景与程序生成的浅灰商务演播室合成，不以色键或方框裁切替代。接口依据官方 `PeterL1n/RobustVideoMatting/documentation/inference.md` ONNX段落；source tensor和四个递归state匹配模型dtype，downsample_ratio固定FP32，递归state逐帧沿用。真实模型推理与边缘质量须另行验收。

生成结果登记新视频、新首帧封面、新形象ID，清除原厂templateId，不覆盖原件或自动切换草稿。单次store.save持久化；保存失败移除本次资产与形象。取消只结束本次进程树并等待退出，然后清理临时目录，不登记成功。所有结果保留qualityAccepted:false，人工预览认可独立处理。

## 文案背景与美颜扩展

avatarOptimize增加 beautyStrength整数0..30（缺省0），background增加content-image/custom-image。content-image需id、backgroundAssetId与64位sourceHash，并在开始及封面完成后核当前确认稿、原形象与原视频。custom-image只校验实际图片资产，本批未提供导入界面。look/background皆original且beautyStrength为0才拒绝无操作。

planAvatarBackground({id,avatarId,aspect})给三个基于规则关键词主题的可修改提示方案；generateAvatarBackground提交真实本地Comfy图片，保存完整来源、原视频/文案hash、prompt/要求、模型graph证据，先预览明确选用；queryAvatarBackground只恢复原unknown，保留中断历史、原远端ID和checkpoint。收取后状态保存失败可复用已登记且hash匹配产物，不重复登记。查询停止保留unknown，只有远端明确失败才转failed。背景变化或文案/人物变化后拒绝跟随文案合成。

美颜传beautyRuntime={python,root}至独立工作器，复用已有MuseTalk人脸解析双权重；class1语义肤区、色度候选与alpha共同限制；只最大脸、漏检帧跳过、全片无有效皮肤失败。回执记录双模型与检测器hash、强度、帧计数和temporalMaskSmoothing:false。RVM使用detail-960-v1内部最长边目标960，上限ratio1，不能保证所有素材边缘质量。背景等比中心裁切；原件保留，qualityAccepted:false。
