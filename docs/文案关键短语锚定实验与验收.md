# 文案关键短语锚定实验与验收

2026-11-15，继续完整复刻。上一批注音生产依赖和实窗验收有实际进展。当前原工作区模型为已有本机qwen3.5:9b-q4_K_M，不改用户配置，不下载模型，不调用原厂付费服务。

## 问题与新假设

既有rewrite-fidelity与rewrite-protection的真实回包表明：JSON编号完整、数字保留或锁定数字/否定整句，仍会丢掉普通动作的修饰范围。例如“可用电源”缩为“插座”，“自己的话”没有明确保留。此前全稿校订、逐分句与整句保护未稳定达到要求，不能重复同一方案宣称改善。

本批假设：先为每个来源分句生成逐字引用的关键短语清单，再让同一现有模型以原厂可见577字符system改写，可能减少此类具体细节损失。该假设尚未验证，锚点覆盖不是事实正确性的充分条件，跨句关系、遗漏短语和新增含义仍需逐句审读。

## 实验方案

1. 先将来源按现有规则拆成保留开头及后文有序句段/分句。每个分句都要有至少一条非空的原文短语引用，严格校验编号和引用确实位于该分句，不接受模型杜撰的“原文”。
2. 清单要求保留对象、动作、修饰范围、数量限制、前后顺序。明确数字/标识及已有有限否定检测继续独立检查。
3. 改写请求保持原厂可见system全文不变，额外本地user包装标明自写来源；逐句保留锚点短语，不把清单或后台说明放进正文。
4. 组装后检查每个锚点在其对应句段出现、原数字和标识保留、未出现已支持的否定反转。缺项失败保留原稿和原始回包，不用原句偷偷回填冒充成功改写。
5. 既有三类反例每类只执行一次清单请求和一次改写请求，不自动重试。逐句看实际清单与输出：事实细节、限制范围、自然口播、重复度、长度和是否新增事实。只有有限样本通过也不宣称原厂效果一致；失败不接入生产。
6. 若三类均未发现明确语义变化，再补两个不同主题的保留样本，观察新题材与关系限定。是否接入正式路径由实际证据决定，不提前承诺。

## 验收与恢复

- 验证清单编号、引用真实性、缺锚点拦截、空白/异常JSON、取消、原稿不被修改；结构测试不代表语义通过。
- 保存模型原始请求/实际模型摘要、回包、锚点与组装稿、错误和逐句审读，使用evidence/validation/rewrite-anchors独立目录，不覆盖旧失败记录。
- 本批实验仅scripts/experiments使用。未决定接入前不改正式生成路由，不改UI、不重新打包来冒认产品改进。原工作区完整JSON和设置字节基线保护。
- 全产品目标仍active。原厂内部云端请求、声音克隆/口型、全部页面与教程、业务生成质量和平台发布继续保留原范围。
