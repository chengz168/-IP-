# 视频拆解原文取证修复

## 问题与原因

结构分析模型复制长段转写时可能修改简繁体、漏字或改写表达。旧校验按逐字连续摘录与来源先后匹配，会拒绝失真的报告；旧报错合并了“原文不存在”和“顺序错误”，未指出出错段落。一次限定纠正也可能重复同样问题。

不能通过模糊匹配解决此问题：少一个否定字就可能改变原意。

## 修改

- 向模型提供按原始顺序编号的连续转写切片，每片最多100个Unicode字符，不改动原文。
- 新报告的钩子、段落和结尾使用 `transcriptRange: [起始编号, 结束编号]` 取证，包含首尾；模型的 `quote` 字段只允许空串，程序直接从原文取回引用。
- 结构化输出按真实来源生成分支：转写编号仅允许来源已有编号；画面依据及未识别项的转写编号必须为空；无画面采样时不提供画面依据分支。
- 旧逐字摘录模式保留。编号和显式摘录同时提供时必须完全一致。
- 校验编号合法性、先后顺序、重叠以及钩子和结尾位置；不采用模糊匹配，不把不存在的摘录判为成功。
- 错误提示说明具体段落，并区分摘录不存在、范围越界、顺序错误和编号正文冲突。
- 原始回复和限定纠正证据保留。纠正请求只追加具体错误原因，不回填整份旧报告，避免长回复挤占本地上下文。仍最多纠正一次，网络或模型调用失败不自动重复提交。
- 编号来源不重复附带整篇转写，避免额外占用本地模型上下文；完整转写仍保存在报告中。

## 范围与限制

这是现有分析契约的有界修复，沿用本地模型、来源采集、视觉采样和时间轴校验，不增加依赖。原文编号只证明引用来自相应来源，不能证明模型分析或来源所述事件真实，也不能纠正语音识别错误。编号切片范围可能包含相邻语句，不是精确语义或剪辑边界；界面的时间来自可对齐的真实识别片段，没有可对齐时间轴时保持未确定。

技术验证覆盖简繁混合、否定字、重复文本、Unicode偏移、编号越界/倒序/重叠、引用冲突、旧引用兼容、真实调用链、来源变化、取消以及画面依据隔离。实际来源的复测记录保存在本机验收目录，不随代码公开提交。

## 本地复测结果

2026年11月28日，在日常工作区通过“解析视频”按钮复测用户失败来源。原始识别文字3232字，来源时长691.58秒；本地模型经过一次限定纠正后生成8段结构报告，页面正常显示。逐项核对所有段落引用与对应原文切片完全一致，来源文件哈希未变化。

本次未开启画面观察。报告通过来源引用和结构顺序校验，不代表其中的人名推断、事件判断或语音识别准确性经过事实核查；内容质量仍未标记为已验收。实际应用已更新并启动核验，草稿、素材、声音、形象和设置与更新前一致。
