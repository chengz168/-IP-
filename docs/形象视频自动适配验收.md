# 形象视频自动适配验收

日期：2026-11-16。用户报告自录形象被整数帧率提示阻止。本次范围为真实视频输入适配；不把媒体转换通过当成口型推理或视觉质量通过。

## 实现设计

- 保留工作器的整数恒定帧率、偶数尺寸、明确帧数与方向检查。普通视频先探测实际帧时间戳；已有可用恒定帧率输入直接复用，不重编码。
- 非整数帧率、可变帧率、缺帧数、奇数尺寸和旋转元数据自动通过 FFmpeg 转成独立 MP4 中间副本：整数帧率、时间轴从零开始、正确旋转、偶数尺寸、最高 3840×2160 像素数。原素材不覆盖。
- 清单分别保存 originalVideo 原文件路径/hash 与 video 实际工作器输入路径/hash，记录转换原因。单形象和多镜头均复用此能力，多镜头继续按首镜头画幅与帧率适配。
- 所有新增 FFprobe/FFmpeg 子进程接收取消信号；任何失败保留失败记录，不登记生成素材。取消不继续准备音频或启动模型。
- 驱动音频范围仍为 1 至 600 秒；形象片段长度不要求等于驱动音频，现有往返复用策略保留。人物与构图仍须满足模型可检出人脸的要求。

## 验收标准

真实 FFmpeg 夹具覆盖 30000/1001、VFR、旋转、缺 nb_frames 容器、正常 CFR、不修改原件与取消。多镜头混合这些输入后仍得到严格可验证输入与完整音轨。本轮不下载模型、不触碰用户当前日常任务。

## 实测结果

- `node --test tests/musetalk-input.test.cjs`：14 项通过、0 失败、0 跳过，退出码 0。
- `node --test tests/musetalk-sequence.test.cjs`：5 项通过、0 失败、0 跳过，退出码 0。
- 命令进程临时加入现有 FFmpeg 路径 `F:\Software\轻语IP智能体\aigc-human\resources\ffmpeg\bin`，未改系统配置。
- 已用真实 FFmpeg 文件验证 30000/1001 → 30 FPS、可变帧率 → 整数 CFR、Display Matrix ±90°、33×47 奇数画幅 → 32×46、MKV 缺 nb_frames → 明确帧数 MP4。每份副本完整解码通过，原文件 hash 不变。正常 30 FPS CFR 直接复用原路径，不重编码。
- 多镜头真实混合 29.97 FPS 旋转输入和缺帧数输入后，规范为 30 FPS、48×64，逐镜头生产输入再次验证通过；现有混合画幅与完整音轨拼接检查通过。
- 已验证提前取消不启动媒体进程；适配转码已开始后取消不写 `input.json`，不继续处理驱动，保留失败记录与原文件。
- 旋转夹具最初使用 `-metadata rotate`，本机 FFmpeg 未写显示矩阵；已改用 `-display_rotation` 并确认夹具确实携带显示矩阵后重新验证通过。没有把无旋转夹具算作旋转通过。

以上定向测试证明输入适配、完整性、取消和拼接契约。过长生成仍受现有驱动音频 1 至 600 秒范围约束；这不是形象片段须与音轨等长，也不是要求形象片段为 1 至 60 秒。
