## 实现与影响

1. server/publish-jobs.cjs：独立发布执行记录，沿用同一Store/runs/publishRecords；预检生成一次性、有时效的确认凭据，绑定具体正文、素材、账号及模式。用户在产品内确认该清单后才上传/提交。自动化验证只到隔离本地浏览器夹具，不向真实平台上传或公开发布。
2. electron/douyin-publisher.cjs 与 account-browser.cjs：复用每账号持久会话、沙箱窗口，以Electron自带debugger的CDP设置本机文件与输入/点击；不安装第二浏览器栈、不导出cookies、不读取验证码。验证码/登录变化交给用户，当前任务据是否越过提交边界记录失败或待确认。
3. 启动后记录immutable snapshot，复制并校验媒体SHA，防止等待时换文件或换稿；提交前再次核对账号代次及输入。每账号串行执行，单一账号跨稿也不能并发上传。
4. 前端保留原版发布页结构，补实际确认/任务进度/逐账号结果和停止；autoCloseBrowser仅直接发布且取得成功证据后关窗，草稿自动清false。旧预检API保留只读语义。
5. Store恢复发布中任务：进入上传或提交边界后程序重启一律unknown，禁止自动重交；边界前interrupted。cancelRun分发到发布任务，不借模型取消逻辑冒称平台已停止。

## 结果、恢复与错误

- 各账号独立记录 queued/running/succeeded/failed/cancelled/unknown，最终只在所有账号都有平台模式对应的新成功提示时succeeded；部分成功须显示部分成功，不称全部完成。
- 设置视频前持久记录upload_started，点击提交前先持久记录submitting。写盘失败不能继续外部动作。提交仅点击一次；超时/断网/关窗/取消若已提交均unknown，保留本次记录及窗口用于人工查平台，禁止盲重发。
- 成功证据保存模式、提示文字、平台URL、时间；跳转、表单填写、上传完成、导出均不是发布成功。封面选择失败立即停止，不默默丢掉用户封面。
- 真正成功记录才可使第七阶段就绪，且必须与当前发布输入和全部账号一致；导出记录继续保留其原有含义。
- 自动关窗失败只作为成功后的附加提示，不改变已确认提交结果。

## 验收与边界

先边界测试一次，再独立源码Electron中的本地HTTPS请求拦截夹具（明确不是平台服务）运行真实媒体文件输入、正文/标签、封面、草稿/直接发布、失败/unknown及停止/刷新；保留错误和运行ID，不因观察超时重建。后台变化后运行全套一次及build/package/verify。最后核验原正式JSON和保护媒体SHA不变、关闭独立窗口，不启动曾遭拒绝的打包EXE。

真实平台未登录与真实成功路径分别记录；缺少真实认证时，不宣称平台已发布、原厂发布完全一致或产品整体完成。不增加新模型或付费请求；C声音相对偏好继续保留。
