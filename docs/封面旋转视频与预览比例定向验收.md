# 封面旋转视频与预览比例定向验收

验收日期：2026年11月17日，Asia/Shanghai。以下是独立媒体处理与CSS几何验收，不能代替完整原生封面编辑操作、原版对照或视频生成模型质量验收。未调用生成模型、登录、付费、下载模型、构建前端、提交或推送代码。

## 发现与定位

初读发现`coverSourceSize`未加入Electron预加载动作白名单，已报告负责人，由负责人修复；本记录不宣称独立完成该入口的原生UI复测。

带90度旋转矩阵的视频，原始编码尺寸320×180、显示尺寸180×320。当前本机FFmpeg为`2025-01-30-git-1911a6ec26-full_build-www.gyan.dev`。即使按显示尺寸缩放封面，该版本直接对带旋转矩阵的源视频和封面进行多输入滤镜合成，仍实际返回`Picture size 0x0 is invalid`。

PNG单独解码、带旋转矩阵视频单独解码、相同PNG与没有旋转矩阵的视频合成均成功。改线程数、PNG格式/解码器、输入顺序、循环、重初始化、关闭自动旋转后显式transpose、在输入选项直接覆盖旋转角度均未解决。上述事实表明失败与当前FFmpeg处理容器旋转信息和多输入滤镜的组合有关；没有据此声称所有FFmpeg版本均存在同一缺陷。

先用`-display_rotation:v:0 0`与`-c copy`真正重封装去除容器旋转矩阵，再显式transpose后叠加封面，实际成功。用旧式`-metadata:s:v:0 rotate=0`重封装在该版本仍保留矩阵，真实失败；没有采用该无效方案。

原横屏预览同时使用最小宽420px和最小高240px，独立浏览器实际尺寸420×240，比例1.75，偏离16:9。负责人修正变量后，重读当前`CoverEditor.vue`的`canvasStyle`表达式，并加载当前真实`cover.css`：在相同400px外容器实测353×198.5625，比例1.7777777777777777，与16:9一致。

## 实现

`server/media.cjs`仅对存在直角旋转信息的源视频，先将视频轨无损重封装为隔离临时MKV，确认编码宽高与原件一致、旋转矩阵已清除，再在最终合成中按90/-90/180度显式旋转。原视频不改动，视频内容只进行最终一次H264编码。

首次将音轨也经过临时MKV，实测AAC首包校验值变化。因此最终实现将音轨直接从原件映射，AAC/MP3继续使用流复制，其他音频编码沿用已有AAC转换行为。源SHA256、音频包校验与后续帧方向均有真实断言。

临时重封装文件和半成品MP4在finally清理；开始处理与提交前检查取消信号。文件名改为UUID，避免并发或同毫秒调用碰撞。非直角旋转明确拒绝，不能冒认已支持任意旋转；旋转路径需要FFmpeg支持`-display_rotation`输入选项，本机配置已实际验证。磁盘写满等资产注册失败没有在本次注入测试中验证，不能视为完整存储事务验收。

## 实测结果

配置真实`FFMPEG_PATH`和`FFPROBE_PATH`后执行`node --test tests/cover-video.test.cjs`：7通过、0失败、0跳过、退出码0，耗时5527.2893ms。原始输出保存在`evidence/validation/cover-review-20261117/cover-video-test-final.txt`。

- 0、90、-90、180四种方向均实际合成；显示宽高正确，输出没有重复旋转矩阵。
- 1秒24帧人工测试源，输出仍24帧，时长偏差小于0.12秒。
- AAC包校验值序列与源文件逐包一致，原件SHA256不变。
- 首帧中心为真实红色封面；第二帧与原件自动旋转后的对应帧平均RGB绝对色差小于12，用于排除后续画面方向被转错，非画质主观评分。
- 无音轨的90度旋转源可导出，未制造虚假音轨。
- 无效封面与预先取消均失败，无资产记录或临时文件残留；45度旋转明确拒绝且无新增输出。

此前首次音轨经过MKV的测试实际失败，修正原件映射后复测通过，不能把首次失败隐藏为一次通过。预先取消验证不等于对运行中每个时刻的取消进行了穷举。

另用真实`createService`、真实`Store`和320×180/90度/1秒10帧人工源实际运行，`report-after-fix.json`记录成功导入180×320、1秒、10帧封面视频，以及独立浏览器正确16:9预览几何。
