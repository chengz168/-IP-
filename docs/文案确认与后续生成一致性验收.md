# 文案确认与后续生成一致性

2026-11-14。本批修复已有确认按钮的保存与输入边界，不把确认等同于模型事实质量通过，也不增加新的人工作业关卡。

## 当前发现

新旧工作流各有一份确认逻辑，都先修改finalText/confirmed再等待save；保存失败会抛出到事件处理器，界面仍留已确认。等待保存时切换任务，后续读取当前draft可能启动另一个任务。Store.updateDraft仅在最终文案变化时失效媒体，没有在原文/改写稿变化时撤销旧确认。必须先记录修改前行为，再修复。

## 实现方案

- 增加共用的纯文本选择/输入快照模块；改写稿只有空白时使用非空原文，不改变正文原写法。
- 增加confirmCopy服务动作，按已保存输入快照核对后原子写入最终文案和确认标记；成功返回完整规范化草稿。写盘失败维持原草稿和媒体引用，不能先宣告已确认。
- 新旧按钮改用共用确认动作。先保存当前编辑，再由服务确认；失败由现有操作提示报告。等待期间任务或文案变化不启动后续流程；连续点击不重复确认。
- 原文或改写稿实际变化时，前端立即、后端保存时撤销旧confirmed；保留独立编辑的最终文案和素材文件。确认新最终文案仍沿用既有下游失效逻辑。
- 自动流程启动固定任务ID，保存后再次核对当前任务，不能因中途切换改为另一任务。

## 验收范围

1. 修改前隔离复现：两界面保存失败残留确认、保存期间切换任务；服务端修改源稿仍保留确认。
2. 有意义的单元/服务测试覆盖失败回滚、并发编辑与快照不一致、重复点击、空白改写回退原稿、原稿/改写改动撤销确认、正常确认和下游引用失效。模型请求0。
3. 隔离源码Electron用真实按钮验证新旧确认、修改后即时撤销、刷新保存、失败提示与已确认状态、自动模式仍固定原任务。注入失败仅是受控故障，不冒称真实模型产物。保存原工作区完整JSON基线，完成后逐字节核对并恢复源码窗口。
4. 两尺寸四字号检查受影响状态及按钮/提示的可见性。沿用原布局，不宣称缺参照状态的原厂像素一致。
5. 适用测试、最终一次全套与构建、目录包哈希；不启动此前自动审批拒绝的打包EXE。模型事实、声音听审和新口型质量继续未验收。

当前是设计，实际结果以本批before-report、desktop-report、test-report和delivery-report为准。
