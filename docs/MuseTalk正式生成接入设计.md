# MuseTalk 本地生成接入设计（2026-11-15）

## 已有事实与范围

用户已批准独立模型与依赖下载，真实8秒240帧候选已经生成。原厂模型及隐藏提示词未知，不能把MuseTalk称为原厂算法。

只读分析 `evidence/validation/musetalk-integration-20261115/source-motion.json` 覆盖原成片6240帧，每15帧取样，共416时刻。源视频593帧。左右背景及肩部两组遮罩的往返循环（包含两端重复帧）平均MAE分别2.0101、1.9735；最近源帧对应下限1.9877、1.9485。前向循环分别10.9833、10.0807。该样本支持采用明确的往返动作复用策略，不证明原厂使用MuseTalk，也不证明口型质量一致。

本批接入现有生成按钮与执行记录，保持H3可选且不自动切换用户配置。MuseTalk明确显示实际模型；不将原版V1/V2标签冒认成本地模型。视频框外动作/背景复用形象素材，配音来自当前驱动。生成质量仍需独立检查。

## 输入与长片规则

保留v1独立短实验契约。新增v2正式输入，接受1至600秒、整数1至60fps、偶数尺寸、单视频流及无旋转的恒定帧率形象。多镜头本批明确拒绝，不能静默只生成首镜头。

v2规范化驱动为16k单声道PCM，按实际采样数计算帧数ceil(samples*fps/16000)，仅为模型特征在尾部增加不足一帧的静音，原音轨不变速不裁切。最终视频时长为整数帧时长，尾部与音轨相差不到一帧。源帧索引为 `n mod (2*N)` 后映射 `i<N?i:2*N-1-i`，保存明确策略与总帧数。前向与反向均包含端点，长片保持连续时间轴。

一次模型加载处理整条音轨；源帧最多缓存一个动作周期。输出逐帧送入FFmpeg，不把长片全部保存为PNG，避免长片磁盘成倍增长。缓存关键点与CPU latent，复用动作帧时重新使用本帧音频条件生成嘴型。实际推理批次、帧数和源索引均留证。

## 产品与状态边界

- 设置增加MuseTalk本地方式、独立目录、完整检查按钮；不新增正常用户流程中的技术面板。
- avatarContext固定本地目录、模型和输入文件属性；目录/协议/驱动/形象变化会使迟到结果保留到素材库但不绑定。
- Runtime沿原avatar任务保存不可变输入快照、进度、工作目录及PID凭据。没有远程ID，不按远程unknown恢复。重开标interrupted，绝不自动启动第二次推理；操作系统持有的文件锁阻止仍活着的旧进程被重复启动，进程退出自动释放。锁文件保留，不按PID删除，以避免不同文件句柄形成双锁。
- 取消先写协作标记，等待当前GPU操作返回；超时则仅终止本次子进程树，确认退出后解除占用，不绑定迟到产物。
- 只有工作器退出0、有效完成回执、输出SHA和完整媒体解码/时序全部通过才入素材库。文件存在不等于成功。
- 暂存目录保留输入、进度、错误、回执；成功后清理可再生成的大体积帧缓存，留下小证据和最终视频。缺空间、模型、依赖、无主体/多个明显前景脸、VFR及取消都应明确失败，不传回原视频冒充生成。
- 打包包括适配器且位于asarUnpack；权重与Python环境仍放已批准的独立目录，不复制进应用包。

## 验收

1. 契约测试：v1不回归；v2任意音频采样、尾帧、往返端点、长片、无效输入、目录变化及迟到绑定。
2. 实际FFmpeg：长短输入、顺序帧写入、完整解码、时间戳、取消终止与失败不登记。
3. 产品实际按钮：新文案 -> 真实IndexTTS新声音 -> MuseTalk新口型 -> 原生完整播放/刷新绑定/剪辑，明确真实推理次数。
4. 全套测试、构建、目录包一致性；不绕过先前EXE启动拒绝。
5. 口型/牙齿/嘴周/连续动作/声音听感及原版同等质量独立待验，不以技术检查通过代替。

## 实际失败后的主体筛选修订

首次正式长片在第282帧失败：同一主体脸被检测器返回一个高置信主框和一个包含于主框的局部重复框；第400帧还有远处小脸。保留检测阈值，以面积占主导且置信度至少0.9、画面占比至少1%的主体框为候选。同脸局部重复框仅在包含度至少0.9且中心距离小于主体对角线0.25时合并；其他人脸面积达到主脸20%时拒绝。连续主体框IoU至少0.35，唯一主体关键点与主框的交集比例至少0.7。全部原始检测与筛选凭据留档，不跳过失败帧，不驱动背景人物。

本批不等于全部功能、模板、UI、交互复刻完成，整体目标保持active。
