# 剪辑成片与发布素材交接修正

2026-11-16。上一批封面视口已完成真实局部验证，整体复刻目标继续进行。本批解决实际制作链的素材交接，不新增平台上传或模型下载。

## 当前证据与问题

`server/service.cjs` 的 `attach` 在手动剪辑完成时直接写 `edit.resultId` 并保存，绕过 `Store.updateDraft`。`Store.updateDraft` 仅把剪辑参数变化视为下游失效，没有把同参数重新生成的新 `resultId` 纳入首帧封面视频和发布包引用的失效条件。发布页与导出服务优先使用 `publish.videoId`，所以旧的默认绑定可能压过新成片。此前真实自动链修后重剪已发生发布仍用旧剪辑，需要另行手选的失败，记录在 `local-full-workflow-20261115/delivery-report.json`。

本批以当前发布页“默认使用上一步视频，也可以手动选择”的可见产品语义和已有真实失败为依据。不声称已取得原厂隐藏服务或全部内部实现。

## 实施范围与行为

1. 手动产物附着统一经过 `Store.updateDraft`，保留已有输入签名检查、任务切换不抢选中项、旧任务返回stale等规则。
2. 参数未变但实际视频、剪辑或封面资产变更时，同样处理依赖：旧首帧封面视频失效；发布若仍指向被替换的上一步结果，跟随有效的新结果。发布若指向另一个独立选择的素材，保持该选择。
3. 重新生成结果或更改发布引用撤销当前发布包的完成引用；历史媒体与历史发布记录保留。写盘失败回滚稿件和当前任务，不能部分绑定新产物。
4. 不新增界面主流程、标签或模板，保持现有布局和交互入口。后端和已有新旧工作流共用同一套结果更新规则。

## 验收与恢复

先补能在旧代码失败的回归，覆盖同参数重新剪辑、旧封面视频、独立发布选择、封面重生成、写盘失败和输入变化。再运行全套检查与构建。在确认现有源码进程无活跃任务后，仅重开该源码进程以加载后端；不运行打包EXE。

使用产品API建立隔离草稿，复用已生成的C人物视频，不提交声音或口型模型。真实按钮完成两次本地剪辑，发布页实际读取新产物，完整播放并刷新，导出包视频SHA与新结果一致；另验独立手选视频不会被替换。验证结束经API清理新增草稿/素材和测试发布记录（若现有API无法删除记录则在独立验证工作区进行，不改写活跃JSON），恢复原稿并核对基线和6保护文件。原有失败保留，不据技术检查宣称真人感或全品一致通过。
