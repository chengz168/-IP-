# 文案写实背景与自然美颜

2026-11-17，当前增量需求。用户选择自然写实场景；既有本人素材、本人身份、衣着与动作保留，已有声音基准C不变。

## 可见流程及验收

视频生成单形象页打开“优化形象” → 选择当前已确认文案对应的背景风格/场景要求 → 用已配置本地Comfy图像模型生成一张无人场景候选 → 查看图片与实际提示词，可重新生成 → 明确选背景 → 调整轻度美颜0至30（0关闭、界面默认12） → 生成独立人像视频副本 → 播放检查并明确选用 → 原口型生成 → 后续剪辑。已有背景导入仅有后端参数支持，本批界面未提供入口。

背景是否契合文案需要人工检查；真实图像生成不等于语义正确。背景是AI创作场景，不能称为真实企业、地点或事件现场。不能把程序绘制的商务背景称为照片。默认只调用本地已配置服务，不自动下载模型或切付费服务。背景模型与非口播图像模型共用同一配置。

人物背景组合采用现有RVM真实alpha与fgr，固定960内部最长边采样候选；本次原片0.5比512尺度改善，但不保证其他素材通用。背景图等比居中裁切，保留真实裁切参数。首次实现静态背景，人物来自原视频连续帧，不能宣称整场景为新动态生成。

轻度美颜须在肤部语义mask内处理，排除眼眉唇鼻、头发、衣服和背景；保留毛孔和五官结构，不重塑脸型，不增加本人没有的表情或动作。复用本机MuseTalk已有BiSeNet权重和独立Python，不下载。没有有效检测/解析则明确报错，不能把整图模糊冒充人脸美颜。需实际记录强度、mask类别/统计、模型哈希与算法参数。几何不变不代表主观身份/自然度已认可。

## 数据与失效

文案背景只取已确认的finalText，保存文案hash、形象ID、背景提示词/用户场景要求、真实模型与种子/graph摘要及候选图资产ID。模型等待期间文案变化不能自动绑定旧候选；预览标为旧文案或拒绝提交。原片/模型/背景文件最终校验后同步登记新副本，失败不覆盖现有形象或当前草稿。

生成背景与合成人像各用独立run；重复点击受锁保护；停止使用既有cancelRun；远程unknown只查询原提交，不能自动重交。刷新后候选可从run/资产中恢复，选择副本后保留当前草稿关联。更换文案、参数或背景会撤下不匹配的人像预览。

## 模块影响与阶段

1. avatar-background独立领域服务负责文案主题提示、候选图生成/查询/证据；复用StoryGenerator和Runtime。
2. avatar-appearance-config/cjs负责新参数、背景引用和哈希、skin解析运行时；portrait worker负责真实合成及肤区处理。
3. AvatarOptimizeDialog负责候选与结果分开确认、强度控制、错误/停止及小窗滚动；preload/service/task-state接入。
4. 完成定向状态回归后，用独立workspace通过真实按钮生成一张文案背景及本人短片；看多帧、完整有声播放，再测口型交接。原首轮透底记录保留。

回退方式：原背景或既有商务背景、美颜强度0，继续保留原形象。本批增量已完成隔离工作区真实按钮短片验证，回执见《人物优化本机配置与验收》；本文不替代质量验收。全项目一比一UI/质量、长片真人感、所有文案/人物的通用效果均不在本批已通过范围。
