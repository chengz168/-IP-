# 文案关键句保留与质量验证

2026-11-14，当前批次设计。整体复刻与生成质量仍未验收，不能据本批宣称100%一致。

## 已确认的问题

原厂可见改写模板577字符和标题模板57字符已提取并内置；完整云端请求、声音克隆及口型内部模型和条件未取得。已有19次真实本地实验仍出现“每人最多带5本书”变为“每个人手里最多只能拿5本”等限制动作变化，继续追加泛泛的保留细节提示不能构成改进证据。

## 本批方案

仅调整原厂可见改写模板的本项目包装层，保留原厂system正文逐字不变。按原有有序句段识别数字/英文型号、中文量词数量及明确否定/限制标记；这些句段由本地保留原句，不交给模型生成。不把“数字还在”当成动作和对象正确。

模型仅改写其余句段，返回编号必须与可改写集合完全一致；拒绝模型额外返回受保护句段、缺失句段和加入新的数字标识。合稿按原顺序插入保留句段，保存保留理由、原句、模型原始回包和实际请求。无可改写句段或其余部分仅原句照搬时明确拒绝，不能把全部拼回原文称为成功改写。

这是保守的有限文本约束，代价是含参数/限制的句段改写自由度降低。未识别的语义、可改写句段的事实、跨句关系和口播自然度仍需逐句审读。保留原句不等于整体语义无误，也不等于原厂同效果。

## 模块与恢复边界

- 新建独立关键句规划/组装模块；只让原厂可见模板生成路径使用，不改用户模板或已保存任务选择。
- 增加质量报告中的保留说明与可改写部分未改写检查，沿用accepted=false及needs-review/rejected。
- 生成仍通过既有输入快照、迟到保护和前后保存；失败保留当前手工稿、原始回包及失败原因。
- 原工作区不改模型设置、不写入实验稿。真实请求及桌面操作均使用新隔离工作区，完成后核对原工作区完整JSON含updatedAt。

## 阶段与验收

1. 先实现独立规划与实验，使用当前已安装9B模型对既有三份虚构输入各请求一次，记录完整system/user/schema/模型摘要与原始回包。失败不盲目重试。
2. 逐句审读全部三稿的数量、否定、条件、对象、动作顺序和口播，明确记录是否仍有遗漏/新义。只有确有改善且未出现新的明确失真，才把该约束接入生产；否则保留实验失败并不接入。
3. 若接入，补已知失真、全保护、额外编号、原句照搬、取消/迟到/刷新保存等有意义的回归检查；源码桌面验证真实结果及质量提示。只改后端时不扩展无关页面样式验收。
4. 完成适用测试、构建/目录包与文件哈希核对，不启动此前被自动审批拒绝的打包EXE。声音听审、真实克隆/新口型和原厂同输入对照继续未验收。

当前尚未完成本批实际请求与产物审读，本文件是设计而非通过收据。

首次预检查发现“一个小标题”和“一组”也锁整句会让普通步骤稿全部受保护、没有可改写空间，实际模型请求为0。调整为有限标记策略：阿拉伯数字/英文标识、非单一中文数量、明确否定/限制仍保留整句；普通“一个/一组”只逐句检查数量原写法，不能据此证明数量限定对象正确。该限制必须在收据写明，不能宣传为所有数量语义已保证。

## 本次实际结论

现有9B模型三次真实请求已完成。通知稿保住带入上限，但产品稿将“可用电源”改为“插座”、“断电”改为“拔电”；步骤稿将“同一主题”泛化为“同类”，并因“一个”原写法未保留被拦截。关键句之外仍有含义收窄、分类依据变化，整句保护方案未达到本批接入条件。

因此阶段2结论为不接入生产，不继续盲目重试。候选模块移至scripts/experiments/rewrite-protection.mjs，正式server/rewrite-generation.mjs和用户模板/设置没有改动。只对独立实验与质量边界做回归和证据核对，无正式生成路径或前端变更，不重复构建/打包，也不进行无关页面验收。声音听审、真实克隆和新口型、原厂同输入对照仍缺，不能承诺原厂同等质量。
