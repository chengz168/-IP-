# 示例二夜间：本地专用口型候选验证

日期：2026-11-15。目标是用户指定的同等质量真实视频能力，仍属于完整产品复刻的一部分。此前H3首帧和Ref2VA已各有真实样片，Ref2VA局部动作更接近但形象及细节不一致，本候选不能作为既定成功方案。

候选为MuseTalk 1.5，源码固定在已研究的官方仓库提交`0a89dec45a0192b824e3cf4daf96c239440c5ed8`。本机新取回该提交的推理、融合、预处理、加载、检测和下载脚本，未执行其模型代码。

模型计划见`evidence/research/generation-chain-20261115/lipsync-plan/plan.json`：11个文件共4,482,904,130字节，4.48290413 GB、4.175029816105962 GiB。只选1.5推理所需主模型、VAE、Whisper、DWPose、面部解析、ResNet和S3FD，不下载1.0主模型或训练用SyncNet。模型计划尚未批准、尚未下载。

HF官方元数据端点连接失败，已保留失败记录；模型版本、文件大小和大权重SHA来自官方Windows下载脚本也使用的镜像元数据。不能把镜像元数据称为独立官方校验。S3FD由固定源码自动下载逻辑发现，原始地址HEAD返回89,843,225字节，完整已知SHA缺失；实际下载后另记录完整SHA，不将本地自算散列冒称官方预期值。

目标独立目录为`D:/AI-Runtimes/super-ip/musetalk-1.5`，不向已有ComfyUI或IndexTTS环境安装依赖。Python依赖下载体积尚未解析，以上字节数仅包含模型与配置。先用现有解释器可用性和Windows wheel解析检查可执行性，再准备依赖；不直接执行官方整包下载脚本。

## 需要封装的实际源码问题

已取回的推理源码通过`os.system`拼接FFmpeg和用户路径，并在任务异常后打印错误继续退出；还会在S3FD缺失时隐式联网。这些逻辑不能原样接入产品。独立工作器需使用参数数组、中文路径、明确退出码、输入/输出清单、文件SHA、取消进程树和仅本目录的临时文件清理。运行前显式检查清单，缺文件直接报告，不在运行时下载。

首轮只处理示例二8秒：原形象视频作为画面来源，复用原成片前8秒音轨，单独标记未新配音。沿原视频宽高和帧率，不重新生成整幅背景；实际输出仍需检查脸部融合。先以小batch和已有显存实际验证，不从官方设备速度推算本机速度。

## 验收与失败恢复

1. 每项输入、模型版本和完整散列在启动前保存，记录本机工作器PID及任务ID；不复用原成片视频流冒充新口型输出。
2. 输出需要完整解码、帧数与8秒驱动覆盖、音轨匹配、真实软件完整播放及刷新绑定。参考视频中原本的头部/视线/衣服/背景保持要逐段对照。
3. 保存可检查的脸部框/融合掩码来源，检查嘴周接缝、牙齿、眼镜、下巴和闪烁。静态背景像素不变不证明口型正确；ASR正文正确不证明同步。
4. 连续口型与听感单独验收，尤其双唇闭合、唇齿音、停顿闭口和声音起止。未验收始终`qualityAccepted=false`、`referenceParityAccepted=false`。
5. 任何失败保留工作目录和清单，报告明确失败或未知。不能因观察超时重复启动同一个任务；先核实原PID/输出清单。未完成或不合格产物不替换既有视频。

只有短样片的效果、资源消耗与取消恢复都有实际证据后，才设计正式单片、长片、多镜头和自动流程接入。当前没有正式接入该候选，没有承诺达到或超过原片。完整208秒及全部UI、模板、功能与交互的一比一仍继续进行。
