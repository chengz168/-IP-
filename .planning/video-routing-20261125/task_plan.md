# 文案驱动的视频制作方式自动路由

## 验收
- 最终确认文案后，按结构/内容证据自动推荐或选择制作方式；低置信度与已有明确手动覆盖不被静默改写。
- 题材类别与制作方式分离：商品介绍可走展示/多镜头；有角色、场次、事件推进的剧情走分镜；普通讲解才走人物口播。
- 第四步、确认文案、自动流程和直接视频生成共用服务器端判定，剧情文案不能落入数字人口型旁路。
- 文案变化让自动路由失效并重新判定，正确清除绑定当前文案的旧下游产物但保留素材文件。
- 自动判定依据和置信度在界面可见，可切换手动并恢复自动。
- 路由单测、相关回归、构建；保护正式本地数据，更新并实际启动验证。

## 阶段
1. 查清用户反馈对应成片与文案，读清剧情服务创建/同步约束。
2. 定义并实现结构驱动视频路由和数据迁移策略。
3. 接入保存/确认/导航/视频服务/workflow/UI同一语义。
4. 有针对性的测试与构建，差异复核。
5. 备份并更新本地工作台，实际启动验证；GitHub只有用户显式要求提交时才发布。

## 暂缓/排除
- 不把一般“商品”字样当成有商品详情资料。
- 不声称模型实际生成多镜头/剧情，除非完成真实媒体检查。
- 不擅自改写草稿、手动选择或下载模型。
